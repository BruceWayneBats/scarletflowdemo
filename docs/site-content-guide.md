# Как менять сайт ScarletFlow

Для владельца продукта: где что лежит, как поменять текст или цену, как опубликовать. Технические подробности — в README.

## Правила текстов

- **Никаких абсолютных обещаний:** «0 ошибок», «100 %», «никогда не пропустим», «гарантируем рост».
- **Никаких выдуманных кейсов, отзывов, логотипов клиентов и цифр.** Раздел кейсов включается флагом `casesEnabled` в `src/config.ts`, только когда есть реальные результаты с согласия клиники.
- **Деньги — только оценка:** «≈», «оценка», «по среднему чеку».
- **Безопасность — только то, что действительно сделано.** Если что-то ещё не готово (например, сервер в РФ), рядом пометка `TODO`.
- **ИИ не врач:** не обещать медицинских результатов, не показывать бота заменой врачу.
- **Тон:** спокойно, коротко, на «вы».

## Цены

- **На сайте:** `src/content/product.ts`, блок `start` (шаги «как мы начинаем»), и вопрос «Сколько это стоит?» в `faq` файла ниши.
- **В чате на сайте:** бот отвечает из базы знаний служебного арендатора. Её меняют в основном проекте, в файле `app/service_tenant_data.py`, затем выполняют `make service-tenant`.

Меняйте цену в обоих местах.

## Ниши

Каждая ниша — один файл в `src/niches/`. Вёрстка, шаблоны страниц и калькулятор общие и слов ниши не содержат (это проверяет `npm run check`).

**Статусы:** `active` — у ниши есть страницы; `soon` — карточка «скоро» в блоке «Для кого» на главной; `hidden` — нигде не показывается.

**Адреса:** первая активная ниша (по `order`) — главная страница сайта, её страницы лежат в корне (`/missed-calls/`, `/demo/`). Каждая следующая активная ниша получает `/<slug>/`, `/<slug>/<страница>/` и `/<slug>/security/`.

### Как добавить нишу

1. Скопируйте `src/niches/clinics.ts` в `src/niches/<slug>.ts` (`slug` — латиницей, например `realty`). Если файл заготовки «скоро» уже есть, замените его.
2. Поменяйте `slug`, `order`, `name`, `teaser` и поставьте `status: "active"`.
3. Перепишите все тексты под нишу: `terms` (слова в падежах для общих фраз), первый экран, проблема, сюжет, шаги, роли, `security` и `safety`, вопросы, подписи и значения калькулятора, типы организаций в `audit`, `cta`, `footer`, свои страницы `pages`.
4. Демо: `demo: true` и раздел `demoForm` — только если бэкенд умеет демо для этой ниши (сейчас только клиники). Иначе `demo: false`, и призывы ведут на аудит.
5. `npm run verify`: TypeScript не соберёт сайт, если у активной ниши чего-то не хватает; проверка покажет нишевые слова, попавшие в общие файлы.
6. Опубликуйте, как обычно.

Чтобы только показать нишу в блоке «Для кого» без страниц, хватит файла с `status: "soon"` и четырьмя полями (как `realty.ts`).

## Страница демо (шаг 9.3)

- **Пример без входа:** готовая организация из профиля ниши; на сервере её создаёт `make demo-example`. Тексты блока — `demoForm.exampleTitle` и `exampleLead` в файле ниши.
- **Вход и квота:** телефон, код из SMS, одно демо за период (по умолчанию 7 дней). Тексты — `account` в `src/content/product.ts`; ошибки — `ERRORS` в `src/lib/api.ts`.
- **Токен входа** хранится в браузере посетителя (`src/lib/account.ts`). После переезда на свой домен бэкенд переходит на cookie, и хранение токена здесь убирается.
- **Согласие на вход** помечено «проверить юристом»; после правки текста поднимите `consentVersion`.

## Тексты согласий

1. Текст — `src/pages/consent.astro`.
2. После любой правки поднимите версию в `src/config.ts` (`consentVersion`, например `2026-12-v2`). Формы отправляют её вместе с заявкой, и в журнале согласий видно, на какой текст согласился человек.
3. До публикации на рабочем домене тексты согласия и политики должен проверить юрист.

## Публикация

1. Правка в файле.
2. Проверка у себя: `npm run verify`. Она ловит ошибки сборки, внешние ресурсы, вес страниц и контраст.
3. `git commit`, затем `git push` в `main`.
4. Через 1–2 минуты сайт обновится. Ход публикации — во вкладке Actions репозитория.

## Если сменился адрес бэкенда

Пока бэкенд за временным туннелем, его адрес меняется при каждом перезапуске туннеля.

1. В основном проекте: `APP_BASE_URL` в `.env`, затем перезапустить `make api`, `make worker` и `make internal-bot`.
2. Здесь: адрес в `src/config.ts` (`apiBase`), затем опубликовать.
3. Если запущен бот ScarletFlow, перезапустите и `make site-bot`.

Без этого не работают формы и чат на сайте.

## Яндекс Вебмастер

1. Добавьте сайт в Вебмастер.
2. Выберите подтверждение мета-тегом.
3. Скопируйте код (значение `content`) в `yandexVerification` в `src/config.ts` и опубликуйте.

На адресе GitHub Pages (подпапка) Вебмастер может не принять `robots.txt` и `sitemap`. Это заработает на своём домене.
